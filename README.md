## ⚠ 제출 전 반드시 처리해야 할 것 — 서비스 접속 링크
원티드 제출 요건은 **"심사 기간 내 정상 작동하는 서비스 접속 링크"**입니다. 지금 이 코드는 로컬(`localhost:8000`)에서만 검증됐고, 배포 전이라 이 상태로는 접수가 안 됩니다.

가장 빠른 무료 배포 경로(택 1) — **둘 다 Claude가 대신 못 합니다.** 계정/로그인이 필요한 단계라 본인 확인이 있어야 해서, 여기 코드는 다 준비해뒀고 실행만 본인이 하면 됩니다.

1. **계정 없이 30초 (권장, 임시용)**: [app.netlify.com/drop](https://app.netlify.com/drop) 접속 → `frontend` 폴더를 통째로 드래그. 로그인 없이 즉시 `https://random-이름.netlify.app` 같은 URL이 생깁니다. 백엔드 fetch가 실패하면 로컬 JS 규칙 기반 폴백으로 자동 전환되므로 데모는 100% 동작합니다. 단, **로그인 안 하고 만든 사이트는 만료될 수 있으니, 이메일로 무료 가입해서 "Claim site" 눌러 고정시켜야 심사 기간(9/21~10/5)까지 안전합니다.**
2. **백엔드까지 배포 (LLM 분석 실제로 보여주고 싶으면 필수)**: `backend/`를 Render.com/Railway/Fly.io 무료 티어에 올리고 `GEMINI_API_KEY` 환경변수 설정(아래 참고). 그다음 `frontend/index.html`에서 아래 두 줄의 `http://localhost:8000`을 배포된 백엔드 URL로 바꿔서 다시 배포:
   - `recalculateMatch()` 안의 `fetch('http://localhost:8000/api/v3/match-jds', ...)`
   - `runAnalyze()` 안의 `fetch('http://localhost:8000/api/v3/analyze-pipeline', ...)`

## LLM 키 (분석을 실제 AI로 켜려면) — Gemini가 기본, 완전 무료
`app.py`는 **Gemini를 최우선으로 시도하고, 없으면 OpenAI, 둘 다 없으면 규칙 기반**으로 자동 폴백합니다. 아래 옵션 중 하나만 하면 됩니다.

**옵션 A — Gemini (권장, 카드 등록 불필요, $0)**
1. [aistudio.google.com](https://aistudio.google.com)에서 구글 계정으로 로그인 → API 키 발급. 신용카드 등록 요구 없이 바로 됩니다(유료 전환 시에만 결제 계정 연결).
2. 로컬 실행 시: `export GEMINI_API_KEY=...` 하고 `python app.py`
3. 배포 시: 호스팅 서비스의 환경변수 설정에 동일하게 등록
4. 무료 티어는 `gemini-*-flash-lite` 계열 모델과 분당/일일 요청 한도가 있습니다 — 데모 트래픽 수준이면 충분하지만, 한도를 넘으면 자동으로 규칙 기반 폴백으로 넘어가서 화면이 깨지진 않습니다.
5. 기본 모델은 `gemini-flash-lite-latest`이고, 안 될 경우 `GEMINI_MODEL` 환경변수로 다른 모델명(AI Studio에서 확인)으로 바꿀 수 있습니다.

**옵션 B — OpenAI (Gemini가 없거나 실패했을 때만 시도, 유료)**
1. platform.openai.com에서 계정 만들고 API 키 발급 (본인 명의 계정/결제수단 필요 — Claude가 대신 만들 수 없음)
2. `export OPENAI_API_KEY=sk-...`
3. **비용**: `gpt-4o-mini` 기준 분석 1건당 보통 0.01달러 미만. 데모/심사 트래픽 다 합쳐도 몇백 원 수준.

둘 다 안 하면 자동으로 규칙 기반 폴백(`engine: "rule_based_fallback"`)만 동작합니다 — 무료지만 "AI 분석"이라고 하기엔 약하니, 최소 Gemini 키(옵션 A) 하나는 넣는 걸 권장합니다. 5분이면 됩니다.

## 로컬 실행 (검증됨)
```bash
cd backend
pip install -r requirements.txt
export GEMINI_API_KEY=...   # 선택, 없으면 규칙 기반 폴백

```
`frontend/index.html`을 브라우저로 열면 됩니다. 화면 상단 배지에 `Gemini LLM 분석 완료 (무료)` / `OpenAI LLM 분석 완료 (유료)` / `규칙 기반 폴백` 중 실제로 어떤 경로였는지 그대로 표시됩니다 — 숨기지 않습니다.

## 이 패키지가 원본 초안과 다른 점 (critique-me 검증 반영, 2라운드 PASS)
- 측정하지 않은 정확도/F1 수치(89.2%, 0.872, N=200)를 신청서·UI에서 제거하고 "측정 계획"으로 대체
- 실제로 호출되지 않던 LLM을 조건부로 실제 연결(`OPENAI_API_KEY` 있으면 진짜 호출), 어떤 경로였는지 응답에 명시
- 근속률 "예측 모델"을 "실측 데이터로 검증되지 않은 예시 공식(illustrative)"으로 재명명
- ROI 4.32억원 계산의 가정(건당 수수료, 개선폭)을 명시하고 실측 아님을 표기
- 캘린더/슬랙 연동 버튼에 "시뮬레이션/샘플 데이터" 라벨 추가 (UI+문서 양쪽)
- CORS `allow_origins="*"` + `allow_credentials=True` 잘못된 조합 수정
- PII 마스킹을 실제 정규식 구현으로 채움 (전화번호/이메일/주민번호 형식)
- **JD 샘플 데이터의 실명 기업(토스페이먼츠/당근/오늘의집)을 전부 가상 기업명으로 교체.** 조사한 적 없는 조직문화 점수를 실명 기업에 붙여놓는 건 그 자체로 평판 리스크라 판단해서, 데모용이라는 게 명확한 가상 기업명(페이플로/로컬허브/홈스타일랩)으로 바꿨습니다. `backend/app.py`, `frontend/index.html` 양쪽 다 반영, UI에도 "가상 예시 데이터" 배지 추가.
- **LLM 엔진을 Gemini 우선으로 변경.** 기존엔 OpenAI(유료, 카드 필수)만 있었는데, 카드 등록 없이 쓸 수 있는 Gemini 무료 티어를 최우선 경로로 추가하고 OpenAI는 폴백으로 내렸습니다. `engine` 필드도 `"llm_gemini"`/`"llm_openai"`/`"rule_based_fallback"`으로 세분화해서 어떤 경로였는지 화면에서 바로 구분됩니다. Gemini 호출은 표준 라이브러리(urllib)만 쓰므로 추가 패키지 설치도 필요 없습니다.

## 추가 안정화 작업 (치명적은 아니지만 실행 안정성 개선)
실제로 서버를 띄우고 curl + Playwright 헤드리스 브라우저로 전체 플로우(프리셋 선택→분석 실행→슬라이더 조작→캘린더/슬랙 시뮬레이션→ROI 모달)를 끝까지 검증했습니다. JS 런타임 에러 0건.
- **키워드 커버리지 확대**: 기존엔 `deep_work`/`social_load`만 텍스트에서 실제로 추론되고 나머지 3축(`pace_predictability`, `async_collaboration`, `boundary_integrity`)은 특수 케이스가 아니면 항상 0.5 고정이었습니다. "로드맵/분기 단위", "비동기/슬랙/스레드", "퇴근 후/야근/칼퇴" 키워드 규칙을 추가해 6축 모두 텍스트에서 반응하도록 확장.
- **입력 검증**: 빈 텍스트·빈 벡터로 호출 시 500 대신 명확한 400 에러 반환하도록 수정.
- **범위 클램프**: 슬라이더 조작 실수나 손상된 요청으로 0~1을 벗어난 값이 오면 서버가 죽는 대신 자동 클램프.
- **예외 처리**: LLM 호출 중 예상 못 한 오류가 나도 500으로 죽지 않고 규칙 기반으로 안전하게 폴백.
- **프론트엔드 방어 코드**: Chart.js CDN을 못 불러와도(방화벽/네트워크 필터 등) 레이더 차트만 빠지고 슬라이더·매칭은 정상 동작하도록 처리 — **실제로 이 검증 과정에서 샌드박스 네트워크가 CDN을 막아서 이 폴백이 실제로 발동하는 것까지 확인했습니다.**
- **중복 클릭 방지**: 분석 실행 버튼을 처리 중 비활성화해서 중복 요청 방지.

## 남은 리스크 (참고만 하세요, 지금은 손 안 댐)
- **디자인이 전부 CDN 3곳(Tailwind, Chart.js, Font Awesome)에 의존**합니다. 발표 당일 행사장 와이파이가 CDN을 막으면 기능은 살아있어도 스타일이 깨진 민짜 화면이 나올 수 있습니다. 가능하면 실제 발표 전에 행사장 네트워크에서 한 번 열어보는 걸 권장합니다.
- Zero-Retention Privacy 배지는 "서버가 원본을 저장 안 함"이라는 구조적 사실이고, PII 마스킹 자체는 정규식 수준이라 완전하지 않다는 점은 문서에 있지만 UI 배지엔 별도 표기가 없습니다.
